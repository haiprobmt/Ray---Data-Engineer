# Ray reliability audit — 2026-09-06

This audit extends the [runtime and live authoring repair](runtime-authoring-repair.md).
It exercises the host runtime boundaries, source validation/review, durable task
state, Fabric action preflight and reconciliation, staged approvals, credential
filtering, SQL reads, and Telegram continuation. Existing unrelated working-tree
changes were preserved.

## Reproduced defects and repairs

| Area | Reproduced failure | Repair and regression coverage |
| --- | --- | --- |
| Item create/update | Source could change or approval could expire during remote preflight reads, yet the write still started. | Recheck the reviewed source and policy after the reads; include expiry in the atomic transition to execution. Four create/update regression cases assert zero writes. |
| Interrupted authoring | Timeout, cancellation, malformed model output, or definition compilation failure left edited files outside the saved review scope. | Persist the original source manifest separately from model output; retain pending source across these failures and process death. Recovery and subsequent review use that baseline. |
| Validation-generated source | Files generated by validation were absent from the required review scope. | Recompute changed files after validation and persist the expanded scope before the reviewer starts. |
| Dependent stage review | Previously completed source stages accumulated as required evidence until the next stage exceeded its budget. | Carry forward unfinished source; completed, validated source stages remain background evidence. Current proposed definitions still require explicit source evidence. |
| Credentials | JSON credential fields escaped the text filter. Model reports and structured Fabric/SQL observations could retain their values. | Recognize quoted credential assignments and refresh tokens; reject credential-bearing task objectives; redact structured fields, credential-named SQL columns, returned reports and stored task results. Tests use synthetic values only. |
| Read failures | Worker timeouts escaped the bounded read-error flow. Oversized SQL previews were reported as general SQL connectivity failures. | Convert timeouts and preview-size failures into fixed, actionable error categories across the subprocess boundary. |
| Cancellation/restart | A cancelled read remained WAITING; recovered tasks and action reports retained stale states. | Save PAUSED task results with cloud eligibility revoked. Interrupted remote execution records BLOCKED/UNCERTAIN consistently in task reports and receipts. |
| Reconciliation | An uncertain job later observed as failed remained UNCERTAIN indefinitely. | Record the terminal FAILED outcome during reconciliation without resubmitting the job. |
| TEST dependencies | Preparing a job before the preceding TEST definition update was approved failed because the remote definition was still the old one. | Stop at the pending exact approval. After success, continue with a fresh source review for the next dependency. Telegram resumes that workflow; the next TEST action needs its own exact approval. |
| Historical receipts | A known failed attempt made corrected work permanently BLOCKED. | Track plans for the current source stage while retaining every historical receipt. Unresolved remote outcomes still block completion. |
| Stale approvals | A later review with identical source bytes could leave an earlier approval usable. | A new source turn supersedes unconsumed READY/PENDING_APPROVAL/APPROVED plans and their pending decisions. |
| Definition paths | Noncanonical aliases could evade the `.platform` restriction or duplicate-path checks. | Require canonical definition-part paths before preparation. |
| Dependency folders | Compilation and validation parsed dependency/cache JSON as authored source. | Apply the repository's dependency/cache exclusions consistently. |
